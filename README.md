# עוזר מחקר וניתוח — מיסוי יחיד ושכר (digitaltax2025-ui)

כלי פנימי עבור אילן גרמן, יועץ מס: עוזר מחקר וניתוח מקצועי לבדיקת
תיקים, בירור דין, הצלבת מסמכים, חישובים וניסוח פניות במיסוי היחיד,
ביטוח לאומי, מע"מ ודיני עבודה. **לא** כלי צרכני, ולא תחליף לשיקול דעת
מקצועי — ההחלטה בכל תיק נשארת אצל יועץ המס.

הפרויקט בנוי לפי אפיון מקצועי מפורט (`docs/agent-brief.md`) שקובע
מדיניות מחמירה: איסור על המצאת מקורות או חיבורים שלא אומתו (נבו, מאגר
מתעדכן), חובת אסמכתה לכל טענה מכריעה, וסימון מפורש של מצב כל מסקנה —
מבוסס במקורות שנבדקו / מותנה בעובדה או מסמך / קיימת מחלוקת / לא אומת.

## מצב הפרויקט ביחס לאפיון

האפיון (`docs/agent-brief.md`) ממליץ להתחיל **בשלב ראשון בתוך Claude
Project**. האפליקציה הזו היא מימוש מקביל שרץ כשירות עצמאי (לא תלוי
בפתיחת claude.ai ידנית) עם אותן הוראות בדיוק, ומכסה חלק מהפער שצוין
קודם מול Claude Project:

- **חיפוש רשת חי** — הצ'אט משתמש בכלי `web_search` הרשמי של Claude
  (`app/api/chat/route.ts`), אותו דבר בדיוק שמופעל בתוך Claude Project.
  זה לא רק כלי לוקאלי — זהו אותו יכולת חיפוש שרת שהאפיון מבקש.
- **קובצי חקיקה שאומתו** — כל קובץ PDF שנשמר ואומת תחת
  `docs/legislation/` (ראו `SOURCES.md` שם) מצורף אוטומטית לכל שיחה
  (`lib/legislationDocuments.ts`), עם `citations` מופעל כך שהתשובה יכולה
  להפנות למספר עמוד מדויק בקובץ. קבצים שלא אומתו — לא מצורפים ולא
  מומצאים; ה-system prompt מנחה לסמן זאת "לא אומת".

מה שעדיין נשאר כפער מוצהר: **המחשבונים** (לא הצ'אט) משתמשים בטבלת
שיעורים קבועה מראש (`lib/taxRates.ts`, `SOURCE_VERIFIED = false`), ולא
בבחירת ערך לפי תאריך והקשר כנדרש באפיון. לכן כל מסך מחשבון חושף במפורש
את טבלת ההנחות שבשימוש ("הצג הנחות מלאות") ומסומן כטיוטה בלבד, לא
כתוצאה מאומתת לתיק.

## מבנה הפרויקט

```
docs/agent-brief.md           # האפיון המקצועי המלא: מפת מומחיות, מדיניות מקורות,
                               # תהליך טיפול בתיק, מבחני קבלה, תוכנית הקמה
docs/system-prompt.md         # פרומפט המערכת — נוסח מדויק של "הוראות מוכנות
                               # להדבקה בקלוד" מתוך האפיון
lib/systemPrompt.ts           # טוען את פרומפט המערכת עבור ה-API
lib/legislationDocuments.ts   # טוען קובצי חקיקה שאומתו מ-docs/legislation ומצרף כמסמכים עם citations
lib/taxRates.ts               # טבלת נתונים כספיים לדוגמה (לא מאומתים) — ראו הסתייגות למעלה
lib/calculators.ts            # לוגיקת החישובים (טהורה, ללא UI)
app/api/chat/route.ts         # נקודת קצה שמזרימה תשובות מ-Claude, עם web_search ומסמכי חקיקה מצורפים
app/page.tsx                  # עמוד הבית: צ'אט + פאנל כלי חישוב
components/                   # רכיבי UI (צ'אט, מחשבונים, פאנל הנחות)
docs/legislation/              # קובצי PDF שאומתו + SOURCES.md (יומן מקורות)
```

## הפעלה מקומית

1. התקנת תלויות:
   ```bash
   npm install
   ```
2. הגדרת מפתח API:
   ```bash
   cp .env.example .env.local
   # ולערוך את .env.local ולהזין ANTHROPIC_API_KEY אמיתי
   ```
   ללא מפתח, פאנל כלי החישוב עדיין עובד; הצ'אט יציג הודעת שגיאה ברורה
   בעברית עד שיוגדר מפתח.
3. הרצה:
   ```bash
   npm run dev
   ```
   ואז גלישה ל- http://localhost:3000

## עדכון נתונים כספיים

הנתונים בקובץ `lib/taxRates.ts` הם ערכי דוגמה בלבד (ר' `SOURCE_VERIFIED
= false` בקובץ). לפני שימוש מקצועי בכלי החישוב יש להחליפם בערכים
מאומתים מרשות המסים והמוסד לביטוח לאומי, לתאריך הרלוונטי לתיק — לא רק
פעם בשנה, אלא בכל תיק שבו נדרש חישוב.

## פריסה (Deployment) — כדי שזה ירוץ כל הזמן, לא רק מקומית

`npm run dev` מריץ שרת רק כל עוד הטרמינל פתוח אצלך. כדי שהסוכן "ירוץ
ברקע" בתור שירות זמין תמיד (לא תלוי במחשב שלך פתוח), צריך לפרוס אותו.
הכי פשוט עם **Vercel** (התאמה טבעית ל-Next.js):

1. push לריפו הזה ל-GitHub (כבר קיים כאן).
2. בכניסה ל-vercel.com → Import Project → לבחור את הריפו.
3. בהגדרות הפרויקט ב-Vercel → Environment Variables → להוסיף
   `ANTHROPIC_API_KEY` (חובה) ו-`ANTHROPIC_MODEL` (אופציונלי, ברירת
   מחדל `claude-sonnet-5`).
4. Deploy. מקבלים כתובת קבועה (למשל `your-project.vercel.app`) שזמינה
   תמיד, לא רק כשהמחשב שלך דלוק.

כל push עתידי לענף הזה יפרוס גרסה מעודכנת אוטומטית. אפשר לפרוס גם
לכל שירות Node.js אחר (Render, Railway, שרת עצמי) — האפליקציה היא
Next.js רגיל ללא תלות ב-Vercel ספציפית.
